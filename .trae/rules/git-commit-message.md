# Git 提交信息规范

## 语言

提交信息一律使用中文书写。技术术语可保留英文形式（如 CLI、API、catalog、executor），但句子的主体必须为中文。

## 详尽性要求

提交信息必须全面、详尽，覆盖本次改动的完整信息，包括：

- 涉及的文件与模块
- 每个功能点的改动内容与实现逻辑
- 修改目的与背景
- 变更类型（新增 / 修改 / 修复 / 重构 / 文档）

禁止以下行为：

- 简化成单句提交（如"修复 bug"、"更新代码"、"优化"）
- 省略必要的实现细节说明
- 因没有协作者而降低完整度；即使独自开发，也必须保持信息的完整与专业

## 结构

提交信息由主题行与正文组成，按以下结构组织：

- 主题行：一句话概括本次提交做了什么，指明改动对象（如"新增 catalog 数据加载与校验"）。
- 正文：逐项列出改动。每个条目包含：
  - 涉及文件或模块
  - 改动内容与实现逻辑
  - 修改目的

多个改动项并存时逐条列出，不合并省略。提交涉及多个层面（如代码 + 配置 + 文档）时，分层说明。

## 示例

```text
新增战术目录的加载与校验

- internal/catalog/loader.go：新增 Load，使用 json.Decoder 流式读取
  catalog/tactics.json，避免整文件常驻内存
- internal/catalog/validator.go：新增 Validate，校验编号唯一性与
  techniques 引用完整性，防止悬挂引用进入注册表
- 目的：让引擎可以基于外部数据驱动执行，符合目录驱动架构
```
